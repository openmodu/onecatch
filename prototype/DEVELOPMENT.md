# Prototype Development Rules

## 目标

这个目录只承载可交互产品原型。它的目标是验证 Oneshot Agent 市场的界面结构、业务闭环和桌面化体验，为后续 Go server 与 Wails v3 落地提供 UI 和交互依据。

## 修改原则

- 每次修改只处理一个明确目标。
- 不引入暂时用不到的抽象层。
- 不把原型逻辑提前拆成过度复杂的模块。
- 不在原型中接入真实支付、真实 OAuth、真实订单接口或密钥。
- 不提交 `node_modules/`、`dist/`、`.npm-cache/` 等可再生成文件。

## UI 规范

- 整体保持桌面应用感：三段式 pane、固定分隔线、独立滚动、紧凑工具栏。
- 左侧用于导航、账号登录、全局上下文。
- 中间用于核心任务工作区：Agent 详情、需求、扣次确认、执行进度。
- 右侧用于 inspector：用量、订单详情、交付物，可折叠。
- 登录入口保留在左下角账号区，支持微信授权登录和 Google 邮箱登录两种模拟状态。
- 不做营销型落地页，不加 hero、大面积渐变、装饰图形或无业务含义的卡片。
- 组件尺寸要稳定，折叠右栏和移动端布局不能导致文本重叠。

## 交互规范

- 所有可见按钮都应有反馈或状态变化。
- 付费逻辑按次数处理：购买次数增加余额，执行 Agent 扣减 1 次。
- 未登录时触发下单必须提示先登录。
- 订单状态和交付物预览保持可点击、可观察。
- 新增交互时同步更新 `PROGRESS.md`。

## 验证

原型改动至少运行：

```bash
npm run build
```

如果修改视觉布局，需要在浏览器中检查：

- 1440px 桌面宽度。
- 右侧 inspector 展开与折叠状态。
- 未登录、微信登录、Google 登录状态。
- 下单扣次与购买次数流程。
- 小屏下单列布局是否可读。

## 与生产代码的边界

- 原型里的 mock data 不是生产数据结构的最终定义。
- 原型里的登录、支付、订单、交付都是前端模拟。
- 生产落地时必须重新定义 API、权限、订单状态机、支付回调和审计日志。

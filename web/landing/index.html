OneCatch 在本地驱动你已经装好的 Codex 和 Claude Code。「实现 → 审查 → 返工」不再是你每次手动重复的动作，而是一张有信号、有上限、中途能插话也能接着跑的状态机。

个人工作台 / 实现 → 审查 loop 

    

  






  

    
能力

    
让 Agent 的每一步都看得见、停得下


    

      

        
换 Agent，不用换读法

        
Codex 走 JSON-RPC app-server，Claude Code 走 --output-format stream-json，两边吐出来的东西格式完全不同。OneCatch 把它们归一成同一组事件：started、reasoning、tool_use、tool_result、file_change、usage、result。你在界面上看到的、写进 run log 的、决定 workflow 往哪走的，是同一份数据。

      


      

        
停得下来，也接得回去

        
跑的过程中可以排队追加指令，也可以打断当前这一轮直接插话。暂停之后按 session ID 恢复——Claude Code 是 --resume，Codex 是 thread/resume——事件继续追加到同一条 run log，不会另起一条。

      


      

        
权限写在每一步上，不是一个全局开关

        
read-only、workspace-write、full 三档，是 workflow 里每个 step 各自的属性。实现那一步可写，审查那一步只读，这是最常见的配法。full 要过一次二次确认，而且不允许跑在远端 worker 上。

      


      

        
写错的 loop 会自己停

        
每个 step 声明它可能输出哪些信号，以及每个信号跳到哪一步。默认最多流转 20 次，连续失败到阈值也停。所以一个绕不出去的循环撞的是上限，不是你一整晚的 token。

      


      

        
数据就是你磁盘上的文件

        
JSON / JSONL 存在 ~/.onecatch，每次运行的事件流在 ~/.onecatch/runs/。可以 grep，可以进 git，可以直接删。没有账号，没有遥测，没有一个云端服务夹在你和 Agent 中间。

      


      

        
把 Linux 目录当本地目录用

        
onecatchfs 用一条常驻的 SSH/SFTP 连接，把 Linux 上的项目挂成 macOS 本地目录。文件内容不落到 Mac 上，只缓存属性和目录列表，默认 1 秒。Linux 那头只要跑着 sshd——不用装 Codex，也不用装 OneCatch。

构建

    
还没有发布二进制，先自己编

    
$ git clone git@github.com:openmodu/onecatch.git
$ cd onecatch
$ go tool wails3 task deps            # 按 lockfile 装 Go 和 JS 依赖
$ go tool wails3 task build:desktop    # 输出桌面开发版本

    
需要 Go 和 Node，版本以仓库里的 go.mod 和 frontend/package.json 为准。想把 Linux 目录挂进来的话，另外装 macFUSE，再跑 go tool wails3 task build:onecatchfs（只支持 macOS）。开发环境是 go tool wails3 task dev:desktop。

  


  

    
不做什么

    
这些事 OneCatch 不打算做

    

      
不托管代码，也不替你跑 Agent。它驱动的是你本机上已经装好的 CLI，用的是那些 CLI 自己的登录和 API key。OneCatch 不转发你的请求，也就拿不到你的 key。

      
不做账号和云同步。换一台机器就是换一份 ~/.onecatch，同步得你自己想办法。这是本地优先的代价，写在这里而不是等你装完才发现。

      
仓库里的市场、登录、计费代码不是产品。那是早期探索留下的，当历史参考保着，不约束现在的本地编排实现。

    

  


  

    
问题

    
你大概会问的几件事

    

      

        和自己开几个终端跑 CLI 有什么区别？
        
区别在「跑完之后」。终端里 Agent 停下来，你得自己判断这轮结果算不算过、要不要返工、返工时把哪些上下文再喂一遍。OneCatch 把这个判断写成 step 的输出信号和跳转表，所以「审查没过就回到实现」是它自己完成的。附带的好处是每一轮的事件、token、改了哪些文件都落在同一条 run log 上，不用回滚终端 scrollback 找。

      

      

        要额外配 API key 吗？
        
不要。OneCatch 起的是你机器上的 codex / claude 可执行文件，认证走它们自己那一套，请求也不经过 OneCatch——所以它既拿不到你的 key，也没法替你计费。

      

      

        能选模型和推理档位吗？
        
能，而且是每个 step 单独选。step 上可以指定 runtime、模型、reasoning effort 和 service tier；没指定的走全局默认。这样「实现」用贵一点的模型、「审查」用便宜的，是配置问题不是改代码问题。

      

      

        支持 Windows 和 Linux 吗？
        
macOS 和 Windows 各有自己的窗口与菜单实现，也各有打包脚本——Windows 走无边框标题栏和原生菜单栏，macOS 走 inset 标题栏。Linux 没有打包目标，Wails 本身支持，但仓库里没验证过。onecatchfs 只有 macOS（依赖 macFUSE）；远端 worker 有 macOS 和 Linux 两个构建目标。

      

      

        可以让它在另一台机器上跑吗？
        
两条路。一是远端 worker：把 step 指到某个 worker 上执行，但 full 权限的 step 不允许这么跑。二是 onecatchfs：把 Linux 目录挂成 macOS 本地目录，Agent 还是在本机跑，只是文件在远端。

      

      

        我的数据会被传到哪里去吗？
        
不会。没有账号系统，没有遥测，没有 OneCatch 的服务端。任务、运行记录、事件流都是 ~/.onecatch 下的 JSON / JSONL 文件。Agent 本身当然要连它自己的模型服务，那部分和你直接用 CLI 时完全一样。

## Design Context

### Users
Oneshot is a local-first desktop orchestration tool for developers who run Codex, Claude Code, and other local CLI agents inside trusted workspaces. They use it to create, observe, pause, resume, and review repeatable implementation workflows, so interfaces should support quick scanning and confident permission decisions.

### Brand Personality
Professional, calm, and precise. The product should feel like a focused native developer tool: trustworthy around filesystem access, compact enough for frequent use, and warm rather than sterile.

### Aesthetic Direction
Follow the project's existing refined, utilitarian desktop language: a softly tinted cream canvas, warm brown identity color, restrained elevation, compact system typography, and dense but breathable controls. Light and dark themes and selectable accents must continue to work through the shared semantic tokens. New surfaces should match the settings forms and shadcn/Radix primitives rather than legacy hand-written form styles.

### Design Principles
1. Reuse shared semantic tokens and UI primitives so every theme and accent remains coherent.
2. Keep frequent developer workflows compact, clearly grouped, and left aligned.
3. Make security and filesystem scope understandable before action without adding visual alarm unnecessarily.
4. Use one clear primary action per surface; keep secondary actions quiet and consistently aligned.
5. Preserve native desktop behavior, keyboard access, focus visibility, and reduced-motion preferences.
